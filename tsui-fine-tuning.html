The freedom left over A 1985 robust-control trick says: satisfy the hard constraint exactly, in an orthogonal basis, and then spend what freedom remains on not being fragile. Most of that has already arrived in fine-tuning, without the vocabulary. One piece has not. Two more are dead, and I killed them on this page.

What a weight matrix actually sees

every key that arrives · and the ellipse they trace
primer · depth 2 · what these matrices are, before what to do with them

A trained model is a few hundred matrices. Teaching it something new means moving numbers inside them — the only question is which numbers, and by how much.

This section assumes you can read linear algebra and have never trained a language model. It builds the vocabulary the rest of the page uses: where the matrices live, what a gradient step actually does, what LoRA restricts, how a closed-form edit differs, and what "input side" and "output side" mean. Nothing here is specific to control theory.

1

Where the matrices are

A transformer is one block repeated N times. Each block reads a vector per token from a running residual stream, computes a correction, and adds it back. Two machines produce that correction: attention, which lets tokens read from each other, and an MLP, which processes each token on its own. The MLP is two matrices with a nonlinearity between them, and it holds about two thirds of the parameters.

The running per-token vector that every block reads from and adds back into. Its width, d_model, is the model's basic dimension — 768 for GPT-2 small, 4096 for Llama-3 8B. Everything a model "knows" at a given point is a vector in this space.

2

You never tell a model a fact. You only make the text of the fact more likely.

This is the single most useful thing to understand, and it is where most intuitions about "teaching a model" go wrong. Training has exactly one objective: given the tokens so far, predict the next one. The loss is the negative log-probability the model assigned to the token that actually came next. Nothing in the machinery mentions facts, subjects, or knowledge.

So when you fine-tune on a corpus of specialist text, you are not inserting propositions. You are running gradient descent until sentences of that kind become likely. Any "knowledge" that results is a side effect of the weights that make that text probable — which is why the knowledge arrives smeared across many matrices, why it can be wrong in ways nobody wrote down, and why the model can lose unrelated abilities in the process.

Full fine-tuning applies that update to every matrix — all 124 million numbers in GPT-2, all 8 billion in Llama-3. That is expensive to compute, expensive to store, and it is the reason the rest of this page exists: everything below is a way of restricting which numbers may move.

Three ways to change a trained model, and they are not variations of each other

The third column is why this page can talk about matrices at all. Once the problem is "solve a linear system subject to constraints", it stops being a training story and becomes a numerical linear algebra story — which is the subject control engineering has been doing since the 1960s.

4

What LoRA's rank actually restricts

A full update ΔW for a 768 × 3072 matrix has 2.36 million free numbers. LoRA writes it as B·A with B of shape 768 × r and A of shape r × 3072, so only r·(768 + 3072) numbers are trainable. At r = 8 that is 30,720 — about 1.3%.

Geometrically: any matrix is a sum of rank-one pieces, Σ σᵢ uᵢvᵢᵀ. Each piece is one outer product — one "ridge" running across the matrix in a fixed direction. Rank r means you are allowed r ridges, and the update must be built entirely out of them. Drag the rank below and watch a surface get assembled from those sheets.

why low rank is not obviously stupid

The empirical finding behind LoRA is that the update a fine-tuning run wants to make is already close to low-rank — adaptation tends to move a model along a handful of directions rather than in all of them at once. Rank is therefore a prior, not just a budget. Whether it is the right prior for injecting knowledge, as opposed to style or format, is still argued about.

5

The MLP as a key–value store, which is what makes a closed-form edit possible

Look at the second MLP matrix — GPT-2 calls it c_proj, the down-projection W, shape 768 × 3072. Its input is the 3072-dimensional vector that comes out of the nonlinearity. Call that vector the key. Its output is a 768-dimensional vector added back into the residual stream. Call that the value.

Because that layer is purely linear, v = W k, it behaves like an associative memory: each key retrieves a value, and the matrix is the whole lookup table, stored as a superposition rather than as rows. That is the observation ROME and MEMIT are built on — and it is why the rest of this page keeps saying "when this key arrives, emit that value" rather than "the model believes X".

K₁ = the keys of the facts you are installing (a handful of columns)
K₀ = keys sampled from ordinary text — the knowledge to be preserved
6

Input side and output side: two different questions about the same matrix

A matrix sits between two spaces, and it can be judged from either. Ask which keys actually arrive and you get a statistic in the 3072-dimensional key space: the covariance K₀K₀ᵀ, called the input side. Ask which output directions the rest of the network is sensitive to and you get a statistic in the 768-dimensional value space, the output side.

They answer different questions and they disagree. A direction can be almost never used and still be one the network reacts violently to. Nearly every published method uses the input side alone; section 04 is about what that misses and section 07 is about where it provably does not matter.

The same weight matrix, judged from both ends

hover the toggle to see which parts of W each criterion calls untouchable

Gramian

Any matrix of the form Σ x xᵀ — an accumulated outer product over a set of vectors. It is symmetric and positive semidefinite, so it has an orthonormal set of directions with an energy attached to each: the directions your data actually uses, ranked. Control engineering calls it a Gramian; machine learning calls it a covariance, a second moment, or a Fisher factor. Same object.

7

Where the "unspent degrees of freedom" are, made concrete

This phrase does a lot of work later, so here it is in numbers. You are editing one 768 × 3072 matrix, so you have 2,359,296 unknowns. Installing two new facts constrains the output on two keys: 2 × 768 = 1,536 equations. Protecting eight sampled keys exactly adds 8 × 768 = 6,144 more. Total: 7,680 equations against 2.36 million unknowns.

Every one of the 2,351,616 remaining directions gives a different matrix that installs both facts perfectly and leaves all eight protected keys perfectly intact. They are not equivalent — they differ in how much they disturb the knowledge you didn't sample. Choosing among them deliberately is the subject of section 06, and the surprise there is that MEMIT is already choosing well, for a reason its authors describe differently.

8

Why none of this reaches attention

Attention has weight matrices too, and you can certainly LoRA them. What you cannot do is the key–value story above. In an MLP the map from key to value is a fixed linear operator, so a fixed set of keys has a fixed covariance and "what this layer stores" is a well-posed question. In attention, the mixing weights are computed from the input itself: which token reads from which changes with every sequence. There is no fixed operator whose input distribution you can take a Gramian of, and no associative table to solve for.

That is why balanced truncation, Gramians and every method on this page land on MLPs and on state-space layers — where a genuine linear recurrence exists — and stop at the attention block. It is a real structural boundary, not a gap in the literature.

What to carry into the rest of the page

A layer is v = W k. The keys that arrive have a covariance, and that covariance is a Gramian. Installing knowledge means forcing W to emit a chosen value for a chosen key; preserving knowledge means leaving its output unchanged on the keys ordinary text produces. Those two requirements are a handful of linear equations against millions of unknowns, and everything interesting happens in the gap.

00 · the one true bridge

A weight matrix with an input distribution is a linear system. That is not a metaphor.

Every transplant on this page rests on one identification. In control engineering you have a plant whose state gets excited by inputs, and a Gramian — a matrix that records how much each internal direction actually gets excited. In a transformer's MLP, the down-projection W maps a key k to a value v, and the matrix everyone writes as K₀K₀ᵀ — the thing MEMIT regularises with and AlphaEdit projects against — is the empirical covariance of the keys that arrive.

That matrix is a Gramian. Same object, same units, same spectral meaning. Forty years of numerical control theory is about what to do with it. So the question worth asking is not "can we borrow the analogy" but which of those forty years already applies, and which parts are provably useless here.

The whole game in one sentence

You want to add something to W that changes its answer on the new fact and changes nothing on everything the model already knows. The second half is a perpendicularity requirement, and perpendicularity is a linear-algebra problem with a forty-year-old literature attached to it — in a different faculty building.

detail · the identification, written out

The layer as linear associative memory

Treat an MLP down-projection as a store of key–value pairs. Stack the keys as columns of K and the values as columns of V. The weights that best recall them minimise squared error, whose normal equation is the classical one:

W K Kᵀ = V Kᵀ ← ordinary least squares, one layer

ROME and MEMIT are exactly this with a preservation term bolted on. Writing K₁ for the new keys, K₀ for the ones already stored, and R = V₁ − W K₁ for the residual the edit has to deliver:

Δ = R K₁ᵀ ( K₁K₁ᵀ + λ K₀K₀ᵀ )⁻¹ ← MEMIT

Why that bold term is a Gramian

For a discrete linear system x⁺ = Ax + Bu the controllability Gramian is P = Σ Aᵏ B Bᵀ (Aᵏ)ᵀ — an accumulated outer product of everything the input can excite. K₀K₀ᵀ = Σᵢ kᵢ kᵢᵀ is an accumulated outer product of everything the data does excite. One is exact over an infinite horizon, the other is a finite-sample estimate over a corpus. Both answer the same question: which directions in this space carry energy, and how much? Both are symmetric positive semidefinite, so both decompose into an orthonormal set of directions with an energy attached to each. Every method on this page is a rule for picking which of those directions to touch.

A recent Kronecker-factored reading of the editing literature makes the identification explicit: the preservation matrix C = K₀K₀ᵀ that MEMIT regularises with is the empirical estimator of the K-FAC input factor E[φ(x)φ(x)ᵀ], which makes covariance-constrained editing an input-side projection under a Fisher metric. Section 07 is about what that framing then rules out.

01 · Tsui's machine

Rotate until the equations form a staircase. Then walk down it. Then count what you did not have to decide.

Tsui's design sequence occupies chapters 5 through 9 of the book, and it is four moves. Only the fourth one is the interesting one — the first three exist to make the fourth one cheap.

move 1 · chapter 5.1

Rotate to a staircase

Apply a sequence of orthogonal reflections until the system matrix has zeros everywhere below the first sub-diagonal. This is the observable Hessenberg form. Nothing about the system has changed — only the coordinates you describe it in.

cost: one QR sweep · O(n³), numerically exact
move 2 · chapter 5.2

Solve by back-substitution

The hard constraint TA − FT = LC becomes a staircase too, so it is solved one row at a time, each row needing only the rows already done. No iteration, no conditioning risk.

cost: O(n²) per pole · and it cannot fail
move 3 · chapter 6.1

Add the second constraint

Impose TB = 0 as well, so the observer does not feed the input straight through to its own estimate. A null-space constraint, stacked on top of the first one.

cost: it shrinks the freedom, it does not break the solve
move 4 · chapters 8–9

Spend what is left

The solution set is not a point. Tsui's claim is that his parametrisation "uniquely enables the full use of the remaining freedom" — and he spends it minimising pole sensitivity: how far the system's behaviour moves when the model you designed against turns out to be slightly wrong.

The punchline is the last readout, not the first three

A staircase does not just make the solve fast. It makes the leftover visible and countable. Tsui's complaint about the textbook approach is not that it is slow — it is that it collapses to one arbitrary solution and throws the rest away, so you never find out that a different solution with identical performance would have been less fragile. Section 06 measures that gap on a real GPT-2 layer: choosing badly within the freedom leaks 7.9–11.4× more onto knowledge you never sampled, at identical edit accuracy.

detail · what the plant and the poles actually are

The setting

A plant is x⁺ = Ax + Bu, y = Cx: an internal state you cannot see, an input you can push, an output you can measure. The eigenvalues of the closed-loop state matrix are the poles, and they set how fast the system settles and whether it rings. Placing them is performance. But A is never known exactly, so what you actually care about is how far a pole moves when A wobbles — and that sensitivity is governed by the conditioning of the eigenvector matrix, not by the pole locations at all. Tsui: "the sensitivity of an eigenvalue is determined by its associated eigenvectors."

Where the freedom comes from

With more inputs than states to constrain, the closed-loop eigenvectors are only required to lie in certain subspaces — a fact due to Moore (1976). That slack is the design freedom, and Kautsky, Nichols and Van Dooren (1985) were the first to search it numerically, minimising the condition number of the eigenvector matrix. It is the algorithm behind MATLAB's place. Tsui's chapter 9.1 presents their iterative method and 9.2 offers his own analytical alternative.

What the two equations mean

T A − F T = L C ← the observer must be consistent with the plant it watches
T B = 0 ← and must not pass the input straight through

The first is a Sylvester equation. Solving it by reducing the coefficient matrices to Hessenberg or Schur form and then back-substituting is the Bartels–Stewart pattern, and it is the standard numerically stable route. Tsui's specific contribution is a form of the solution in which, quoting the preface, "all eigenvalues of F and all rows of T [are] completely decoupled" — which is what turns a single global nonconvex search over the leftover freedom into a set of small independent ones.

One honest limit on this description

The chapter structure, the preface claims and the index terms above are verified from the book's own front matter. Chapter 5's body was not available to read, so the back-substitution mechanism described here is inferred from that structure plus the standard Sylvester literature rather than quoted from Tsui's page.

02 · three ways to obey a constraint

Ask nicely, correct after every step, or change coordinates so that disobeying is unrepresentable.

This is the single most transferable idea on the page, and it costs nothing to see. You want an update that leaves the old knowledge untouched: Δ·k = 0. That is a line in parameter space. You also want the update to fit a new fact, which pulls you toward a target somewhere off that line. Three strategies, and they are not equally good.

exact at rest · per-step cost, and it fights the optimiser's momentum
③ change coordinates

Re-parametrise

Write the update as Δ = B·(Uᵀ) where U is an orthonormal basis of the permitted directions, and train B freely. Violating the constraint is now unrepresentable. Plain unconstrained gradient descent, exact to machine precision, forever.

one basis, built once · no penalty weight, no per-step projection

This is Tsui's move, and the field has already found it

Option ③ is chapters 5 and 6 in miniature: absorb the hard constraint into the coordinates, then optimise without one. And in fine-tuning it is already published — LoRA-Null freezes the down-projection A inside the activation null space so that BAX = 0 keeps holding as B trains; NB-LoRA does it for post-RL reasoning retention; Null-LoRA builds the basis from the weights instead of the activations. NESS states the equivalence formally: projecting gradients and re-parametrising impose the same geometric constraint, and "the difference lies only in how it is implemented."

So: not a gap. A convergence. Which moves the interesting question to the two things the papers do not discuss — how you choose which directions go into that basis, and what you do with the freedom that survives the constraint. One of those two turns out to be quietly solved already, in a line of MEMIT nobody reads that way. The other is open.

detail · the three updates, written out

Let p be the protected direction (a key that must keep working) and t the target the new fact pulls toward. Objective ½‖δ − t‖², constraint pᵀδ = 0.

① penalty L = ½‖δ−t‖² + ½λ(pᵀδ)²
δ* = (I + λppᵀ)⁻¹ t → pᵀδ* = pᵀt/(1+λ‖p‖²) ≠ 0

② projection P = I − ppᵀ/‖p‖²
δ ← P(δ − η∇L) → pᵀδ = 0 at rest, but P applied every step

③ re-param U = orthonormal basis of null(pᵀ)
δ = U z, train z → pᵀUz ≡ 0 identically, for every z

Why ① never gets there

The penalty solution's violation is pᵀt / (1 + λ‖p‖²) — it decays like 1/λ and is never zero. In a single edit that is invisible. Across a sequence of edits it accumulates, which is exactly the failure AlphaEdit was written to fix and which section 05 measures.

Why ③ is not merely ② done tidily

Three concrete differences. Gradients are exact: in ② the reported gradient is not the gradient of the constrained problem, so Adam's second-moment estimates are computed on a quantity that is about to be partly discarded. Momentum is consistent: a projected optimiser carries momentum that keeps pointing out of the feasible set. The parameter count drops: in ③ you store z, of dimension equal to the permitted subspace, instead of a full δ plus a d×d projector.

There is a documented cost, and it is real: a fixed basis has a plasticity ceiling. One recent analysis shows that with the down-projection frozen, the first-order loss decrease is gated by the projected energy ‖AXᵀ‖² — if your permitted subspace has little overlap with what the new task actually excites, learning simply stalls. Critics of the fixed-basis family (aimed at BiLoRA and PLAN) add that hard orthogonality "may fail to uncover truly isolated subspaces while discarding task-shared directions."

03 · why the basis must be orthogonal

Any basis of the permitted subspace satisfies the constraint. Only an orthogonal one leaves your optimiser intact.

Here is the part of Tsui's rationale that transfers word for word and is almost never stated in the fine-tuning papers. From the preface, on why he uses the Hessenberg form at all: "Every effort has been made to use reliable computational methods … such as the computation of Hessenberg form (instead of the canonical form) and orthogonal matrix operation (instead of elementary matrix operation)."

A canonical form is prettier — more zeros, more structure. Getting to one requires elementary row operations, which are not isometries: they stretch some directions and squash others. Once you have optimised in stretched coordinates, every length you measured is a lie about the space you actually care about. What this means for a LoRA adapter, concretely

If you build the permitted-subspace basis with a QR or an SVD, you get an isometry, and a gradient step of size η in the reduced coordinates is a step of size η in the model's weight space. Your learning rate, your weight decay and Adam's per-coordinate scaling all keep meaning what they meant. Build the same subspace from, say, a Gaussian-elimination basis or an un-normalised set of spanning vectors, and each coordinate silently acquires its own effective learning rate, in proportion to that basis vector's length. The constraint is still satisfied exactly. The optimisation is now quietly wrong.

detail · the arithmetic of a skewed basis

Fit ½‖Bz − t‖² over reduced coordinates z, where B is the basis of the permitted subspace. The gradient is Bᵀ(Bz − t), so the curvature seen by the optimiser is BᵀB — the Gram matrix of the basis you chose, which has nothing to do with the problem.

orthonormal BᵀB = I → condition number 1 · circular contours · one step per direction
skewed BᵀB = G ≠ I → condition number κ(G) · elongated contours · O(κ) steps

Gradient descent on a quadratic with condition number κ needs about κ·log(1/ε) iterations, and the largest stable step size is 2/λ_max(G) — so a badly scaled basis both slows you down and forces the learning rate down. Adam hides some of this by rescaling per coordinate, which is exactly why the damage is easy to miss: the run still converges, just to a different point, more slowly, with your weight decay applying unequal pressure across directions that were supposed to be equivalent.

This is also the honest answer to "does the Hessenberg form itself transfer?" For a single weight matrix, no — there is no iterated A to reduce, and the staircase algorithm degenerates to one QR, which is what the null-space papers already do. What transfers is the reason Tsui insists on it: orthogonal operations only, all the way through, because the measure of merit at the end is a norm.

04 · what "null space" actually means here

In 4096 dimensions with 100,000 sampled keys, the null space is empty. Every method on the shelf uses a threshold instead.

This is the detail that turns a tidy story into a research question. AlphaEdit's guarantee is that the edit lies in the null space of the preserved keys — but with 100,000 Wikipedia triples encoding K₀ in a space of a few thousand dimensions, K₀K₀ᵀ is full rank and its null space contains only the zero vector. What every one of these methods really does is keep the eigenvectors whose eigenvalue falls below a threshold and call that span the null space.

Which is to say: they perform a truncation of a Gramian, on the input side, with a threshold picked by hand. Control theory has a forty-year-old answer to precisely that question, complete with error bounds, and it says the one-sided criterion is the wrong one.

The mistake the one-sided rule can make

A direction gets declared safe because the training corpus rarely excites it. But "rarely excited" is not "harmless". If that same direction is one the downstream layers are very sensitive to, then a small, perfectly legal edit inside it produces a large change at the output — on inputs your calibration set happened not to contain. Switch the toggle above to balanced and the bars reorder: some of the quietest input directions are the loudest output ones.

In control engineering this is not a subtlety, it is the founding result of model reduction. A state is safe to delete only if it is both hard to excite and hard to observe, and the correct ranking is by the Hankel singular values — the geometric mean of the two Gramians — not by either one alone. Truncating on input energy alone is the textbook error that balanced truncation exists to correct.

detail · balanced truncation, and what it would mean here

The control-theoretic recipe

Given a controllability Gramian P (what the input can excite) and an observability Gramian Q (what the output can see), the Hankel singular values are

σᵢ = √( λᵢ( P Q ) ) ← the eigenvalues of the product, not of either factor

Balance the coordinates so that P = Q = diag(σ), truncate the small σ, and you inherit a hard error bound: the H∞ distance between the original and reduced system is at most twice the sum of the discarded σ. That bound is the thing the hand-set threshold in the LoRA literature does not have.

The mapping into a transformer layer

P ↔ K₀K₀ᵀ = E[φ(x)φ(x)ᵀ] K-FAC input factor · used by everyone
Q ↔ E[g gᵀ] K-FAC output-gradient factor · used by almost no one
σ ↔ √λ(PQ) the ranking that would replace the threshold

The output factor is not exotic — it is the other half of the Kronecker-factored Fisher, F ≈ A ⊗ G, which pruning has used since EigenDamage (2019). What the editing and null-space-LoRA literature does is adopt A and quietly set G ≈ σ²I, a maximum-entropy stand-in for gradient information it does not have. That is a defensible default and an unexamined one.

Where this has already been done, elsewhere in the stack

  • State-space models: CompreSSM balances an LRU layer by both Gramians and truncates mid-training, proving the Hankel values move boundedly between gradient steps via Weyl's theorem. HSVR (NeurIPS 2025) regularises the Hankel spectrum during training so later truncation is nearly lossless.
  • Quantisation: KRONQ (COLM 2026) reports that output-side factor diagonals "vary by orders of magnitude" and folds H_G into the objective, calling it "a dimension largely overlooked by existing compensation-based methods."
  • Pruning compensation: COEC applies alternating left and right orthogonal rotations rather than a single output-side one — two-sided, for the same reason.
  • Editing and null-space adapters: input side only.

Note the caveat that section 07 spends in full: the SSM case is the one where the machinery applies with no analogy at all, because an SSM layer is a linear recurrence with genuine Gramians. Attention is not, which is why none of this reaches the attention blocks.

06 · what the leftover freedom is worth

The constraints pin down a sliver. Which point you pick in the rest is worth about 2× — and the multiplier is the condition number of the Gramian.

This is move 4, and it is where I expected to find an untouched research direction. What I actually found, after computing it, is that the most important half of it is already being done — by a line of MEMIT's derivation that is usually described as something else entirely. The other half measured out at about one percent, and I am retiring it below.

Start by counting. In the panel's setting — 40-dimensional keys, 6 output dimensions, 8 protected keys held exactly fixed and 2 new facts installed exactly — the constraints use 60 numbers and leave 180 free parameters. For a real LLaMA MLP projection the same count runs to about 10⁷. And the solution set is affine: blend any two valid updates in any proportion and the blend is still valid. So you can literally walk a straight line between two solutions and never once break the constraints.

Finding 1 · at κ = 1 the two choices are identical, to the last digit

Drag κ to the far left. The gap closes completely. If the keys arriving at a layer were isotropic, the leftover freedom would be worth nothing and every solution in it would be equally good. This is why the effect is invisible in any small hand-built example — including the first two I tried, which is how I found out. Real activation Gramians are ill-conditioned by hundreds to thousands, which is the only reason any of this matters.

Finding 2 · MEMIT is already doing Tsui's move 4, under another name

The Gramian-weighted choice is not a new proposal. Look at where the covariance sits in the published update:

Δ = R K₁ᵀ ( K₁K₁ᵀ + λ K₀K₀ᵀ )⁻¹  → carries C⁻¹ on the right

That is the solution to min tr(Δ C Δᵀ), which is min E‖Δk‖² — minimum expected leakage over the key distribution. The covariance term is almost always explained as a regulariser that protects old knowledge. It is doing something more specific than that: it is the selection rule within the leftover freedom. Strip it out and replace it with a plain pseudo-inverse and you still satisfy every constraint exactly, you still install every fact, and — measured on GPT-2 three panels below — you leak 7.9–11.4× as much onto knowledge you never sampled. That is Tsui's entire argument about the separation principle, arrived at independently, in a different decade, by people fixing a different bug.

Finding 3 · the refinement I expected to matter, retired

My prediction going in was that average-case is the wrong criterion and the worst case is what breaks models, so replacing min E‖Δk‖² with min max‖Δk‖ — the H∞ move from section 07 — should buy something on top. I computed it. Over the freedom set, the worst-case optimum sits within about 1% of the average-case optimum in every geometry I tried, and both sit well inside the gap to the Euclidean choice. On this evidence the minimax refinement is not worth the semidefinite program it would cost. Two of my four candidate directions are now dead: this one by measurement, and the output-side weighting by the algebra in the next section.

Finding 4 · measured on GPT-2, because the toy’s 2× needed checking

Everything above this point was synthetic. The obvious objection was that a real layer’s key covariance might be close to isotropic in the directions the freedom occupies, in which case finding 2 collapses to a curiosity. So I measured it on two models: GPT-2 small (124M, key dimension 3072, layers 3/6/9) and GPT-2 XL (1.5B, key dimension 6400) — the latter being the model ROME and MEMIT were actually developed on, with layers 14 and 17 inside MEMIT’s published critical range and layer 36 well outside it as a control. Leakage is scored on keys from documents that contributed to neither the Gramian nor the constraints.

It does not collapse, and it does not wash out at 12× the size. On GPT-2 XL, replacing MEMIT’s covariance term with an identity matrix leaves the edit equally accurate and multiplies average leakage by 6.6–11.9×, against 7.9–11.4× on GPT-2 small — the same effect, at the same size, in a key space twice as wide. The anisotropy that drives it is scale-invariant in the way that matters: the fraction of directions carrying the energy is 0.48–1.05% on GPT-2 XL against 0.57–0.90% on GPT-2 small. Twelve times the parameters buys no isotropy at all.

What this does and does not establish

It establishes that the covariance term in a published editor is not a formality: on both models, replacing it with the identity leaves the edit just as accurate and multiplies collateral leakage by 7.9–11.4× (GPT-2 small) and 6.6–11.9× (GPT-2 XL). It also answers the question this page previously left open — the effective conditioning of a real key Gramian is nowhere near 1. Across the six layers measured the participation ratio runs 17.5–27.5 of 3072 on the small model and 30.8–66.9 of 6400 on XL, with a single direction holding 11.8–23.1% of all the energy. Real activations are about as anisotropic as data gets, and adding parameters does not make them isotropic.

It also rules out one alternative explanation. Layer 36 sits outside MEMIT’s critical range, where no editing method operates, and it behaves like the others — so this is a property of MLP key statistics in general, not an artefact of the layers people happen to edit.

It does not establish a benchmark result. My edit targets are structurally realistic but synthetic — I make one real key emit what another real key emits, rather than running ROME’s optimisation for a genuine fact — and leakage onto held-out keys is a proxy for downstream damage, not a measurement of it. Both models are also far smaller than today's frontier systems, though GPT-2 XL is the one ROME and MEMIT were themselves benchmarked on, so it is not a toy. The honest claim is about the geometry, and the geometry is unambiguous.

detail · the weighted solution, and the mistake I made deriving it

The general weighted minimum-norm solution

minimise tr( Δ M Δᵀ ) subject to Δ K = R

stationarity: 2ΔM = Λ Kᵀ → Δ = ½ Λ Kᵀ M⁻¹
constraint: ½Λ = R ( Kᵀ M⁻¹ K )⁻¹
solution: Δ = R ( Kᵀ M⁻¹ K )⁻¹ Kᵀ M⁻¹

To minimise expected leakage you set M = C, the key covariance — and the solution then carries C⁻¹. The inverse is easy to put on the wrong side, and I did: my first run passed the covariance where its inverse belonged, which minimises tr(ΔC⁻¹Δᵀ) — deliberately spending the update in the directions the data uses most. It leaked about 1.5× more than plain Euclidean, monotonically in κ, which is how the error announced itself. Worth recording, because the sign of that effect is the whole point: put the Gramian on the correct side and you are protecting old knowledge; put it on the wrong side and you are systematically destroying it, with a healthy-looking loss curve either way.

Why an affine solution set lets you interpolate

The feasible set is {Δ : ΔK = R}. If ΔK = R and Δ′K = R then for any u, ((1−u)Δ + uΔ′)K = (1−u)R + uR = R. So the walk in the panel is exact everywhere, including outside the segment — which is why the slider extends past both endpoints and the fit error stays at 10⁻¹⁵ throughout. The two named endpoints are the Euclidean minimiser (M = I) and the Gramian minimiser (M = C).

The measurement that resolved this, and how it was set up

The question this section originally left open was whether a real layer's key covariance is anisotropic in the directions the freedom occupies, or only in the few enormous ones the constraints already pin down. Finding 4 settles it. The setup, so the numbers can be argued with:

  • Keys. The input to mlp.c_proj — the post-GELU activation, exactly the vector MEMIT calls a key. Dimension 3072 at layers 3/6/9 of GPT-2 small; dimension 6400 at layers 14/17/36 of GPT-2 XL.
  • Gramian. The uncentered second moment over 93k tokens of Wikipedia for the small model and 172k for XL — the same statistic and the same source MEMIT uses, at a smaller sample size. The XL corpus was enlarged deliberately so that samples per key dimension (26.9) stays comparable to the small run’s (30.3), rather than degrading with the larger dimension: a weaker result had to mean a weaker effect, not a worse-estimated covariance.
  • Split. Leakage is scored on every key the held-out documents produce — 1,728 of them for GPT-2 small, 3,168 for GPT-2 XL — from documents that contributed to neither the Gramian nor the constraints. Sampling noise in the Gramian can therefore only penalise the Gramian-weighted method, never flatter it — the measurement is conservative in the direction that matters.
  • Edit. Eight protected keys held exactly fixed, two new facts installed exactly, the residual built by making one real key emit what a different real key emits. Structurally realistic; not an actual ROME-optimised target.
  • Robustness. The ratio holds across all six layers measured and both models, and is flat in the ridge λ over every value tried — three orders of magnitude on GPT-2 small, two on XL, with the XL figures stable to two decimal places. The two solutions' row spaces have a maximum principal angle of 90°, so they are not small perturbations of one another.

The diagnostic that answers the original question is the participation ratio, (Σλ)² / Σλ² — the honest count of how many directions carry the energy. It comes out at 17.5 to 27.5 out of 3072 on GPT-2 small and 30.8 to 66.9 out of 6400 on GPT-2 XL, with the top single direction holding 18.1–23.1% and 11.8–17.7% respectively. As a fraction of the space available that is 0.57–0.90% against 0.48–1.05% — indistinguishable. Meanwhile 99% of the energy needs thousands of directions, so the tail is long and nearly flat. Both are true at once and not in tension: a few dozen directions dominate, and the last percent of the energy is smeared across the rest.

07 · where the transplant is provably useless

Put the output-side Gramian into a closed-form editor and it cancels out of the algebra. Here is the cancellation.

A page that only lists reasons the idea works is not worth reading. So: the most obvious version of the section-04 proposal — "weight MEMIT's objective by the output side too" — does not merely fail to help. It provably changes nothing, and you can watch it disappear in four lines.

minimise tr( Q Δ C Δᵀ ) subject to Δ K₁ = R

stationarity of the Lagrangian: Q Δ C = Λ K₁ᵀ
so: Δ = Q⁻¹ Λ K₁ᵀ C⁻¹
impose the constraint: Λ = Q R ( K₁ᵀC⁻¹K₁ )⁻¹
substitute back: Δ = R ( K₁ᵀC⁻¹K₁ )⁻¹ K₁ᵀ C⁻¹   ← Q is gone

The exact equality constraint uses up every output-side degree of freedom, so any output-side weight you place on the objective is annihilated on the way to the solution. The Kronecker-factored analysis of the editing literature states this directly: because the constraint leaves no output-side degrees of freedom, the output factor cannot affect the closed-form solution. One of the four ideas on my list died here, and it is the one that sounded best.

Which is itself the most interesting thing on this page

Control theory has seen this exact cancellation before, and its response was to change the objective. A quadratic trace criterion is H₂ optimal control — average-case energy, which is what MEMIT, AlphaEdit, LoRA-Null and every ridge-regularised editor are minimising. The field moved to H∞ — a minimax criterion over the worst input direction — precisely because the quadratic one is blind to worst cases, and Tsui's robustness measures are on that side of the line.

So the accurate diagnosis is not "the editing literature forgot the output side". It is: the editing literature is solving an H₂ problem, and fragility is an H∞ question. Change the norm from trace to spectral and the cancellation stops, because the minimax solution genuinely depends on both weights. That is the same reason the fragility curve in section 06 is drawn with σmax and not with a Frobenius norm.

Attention has no Gramians

Everything above concerns a linear map with an input distribution — an MLP projection. Self-attention is not a linear recurrence: there is no state to excite and nothing to accumulate an outer product over. This is why every successful balanced-truncation transplant lands on state-space layers and stops there. If you want the machinery inside a modern model, the place it legitimately applies is the SSM half of a hybrid.

Depth is not time

The tempting move is to treat layer index as the time axis and the residual stream as the state, which would make the whole network one dynamical system. A DMD study of Vision Transformer blocks found a low-rank linear operator predicts well for spans of about four blocks and then fails to beat an identity baseline when propagated to the final layer. The residual stream is too close to the identity for depth-as-time to pay. (This one I have from a secondary summary, not a direct read of the paper.)

The Hessenberg form itself does not transfer

For one weight matrix there is no iterated A, and the staircase reduction collapses to a single QR — which is exactly what LoRA-Null and NESS already compute. The staircase only earns its keep where several layers are coupled, which is section 08.

And the plasticity ceiling is real

Confining the adapter to the quiet directions works only if the new task has energy there. With the down-projection frozen, the first-order loss decrease is gated by the projected energy ‖AXᵀ‖²: pick a basis the new domain does not excite and the run converges to nothing, on schedule, with a healthy-looking loss curve for the first few hundred steps.

08 · the one place the staircase belongs

MEMIT spreads an edit across six layers by dividing by the number of layers left. That is a placeholder where a computation should be.

MEMIT does not edit one matrix. It identifies a range of critical MLP layers by causal tracing — for GPT-J, layers 3 through 8 — optimises the residual once at the top of that range, and then distributes it downward with a coefficient that decays as 1/(L − ℓ + 1): the remaining residual divided by the number of layers still to go.

That rule contains no information about the network. It is a reasonable guess that a distributed update is gentler than a concentrated one. And the question it is standing in for — how much of a change injected at layer ℓ actually survives to the output? — is a reachability question over a composition of maps, which is the one thing a staircase reduction is built to answer.

The critique is already in the literature; the replacement is not

The even-spreading heuristic has been challenged from both directions. BLUE reports that the contribution of distributed residuals "drops sharply" with distance from the top of the range, that thin spreading introduces accumulating weight-shift errors, and it responds by editing only the first and last layer and leaving the middle alone. A separate line argues the spreading runs the wrong way, replacing backward interpolation with forward replay. Both are empirical corrections to a coefficient. Neither computes the reach.

Honest label on the panel: the MEMIT coefficients are the published rule, exactly. The reach profile is illustrative — a plausible shape for how much of an injected change survives composition, not a measurement. Measuring it for a real model is the experiment, and it is a forward-pass-only experiment: perturb the layer-ℓ output along a set of directions, measure the induced change at the top of the range, and you have the matrix that should be setting those coefficients.

09 · scorecard

Two moves already arrived, one is dead on arrival, and one is sitting unspent.

Absorb the constraint into the coordinates already done

Tsui's chapters 5–6. In fine-tuning this is LoRA-Null, NB-LoRA, Null-LoRA and NESS, which reached it independently and — in NESS's case — proved the equivalence with gradient projection explicitly. Nothing left to contribute except the framing.

Use orthogonal operations throughout, never merely valid ones arrived, unstated

The null-space papers do use SVD and QR, so they get the isometry for free. What they do not state is why it matters — that the Gram matrix of your chosen basis becomes the curvature your optimiser sees, so a non-orthogonal basis for the same subspace silently rescales your learning rate per direction. Tsui says this out loud in his preface, in 2004, about a different problem.

Rank the directions by both Gramians, not just the input one open · half of it

Every method thresholds the input-side Gramian by hand and calls the tail a null space. Balanced truncation answers exactly that question with an error bound. But section 07's cancellation kills the naive version: for a one-shot exact editor the output weight is inert. It survives for basis and rank selection, and for iterative training where the fit is soft. Cheapest real experiment on this page.

Choose deliberately within the leftover freedom already done · unnamed

I went in expecting this to be the open one. It is not — but it is worth far more than I thought. On a real GPT-2 layer the choice within the freedom is worth 7.9–11.4× in leakage onto unsampled knowledge (6.6–11.9× on GPT-2 XL), at identical edit accuracy, and the multiplier is the anisotropy of the key Gramian, whose participation ratio is 27.5 of 3072 and 66.9 of 6400. The choice is nonetheless already being made correctly: MEMIT's covariance term is the weighted-minimum-norm selection rule, not the regulariser it is usually called. Tsui's move 4, performed without the vocabulary, and empirically load-bearing. The minimax refinement I expected on top of it measured 1% and is retired.

Assign eigenvalues to install knowledge dead

Pole assignment presumes you know the spectrum you want. "Knows nephrology" has no spectral specification, so there is no target to assign. This is a modelling gap, not a numerical one, and no amount of better linear algebra closes it. The half of Tsui's book that transfers is the robustness half — how to inject without destroying — because that genuinely is a sensitivity problem.

What I would run first, in order

1 · Two-sided basis selection. The one surviving proposal. Replace the eigenvalue threshold on K₀K₀ᵀ with a ranking by √λ(PQ), estimating Q from a few hundred backward passes. First report whether the chosen subspace differs at all — if the two rankings agree, the whole idea is moot and that is worth knowing in a day. Section 07's cancellation says this cannot help the one-shot solve, so run it where it can: on basis and rank selection, and on iterative LoRA where the fit is soft.

2 · Done, and it came back louder than expected. This slot used to read "measure the effective conditioning of a real layer, because the toy's 2× may not survive contact." It is now measured, in section 06: the participation ratio is 27.5 of 3072 (and 66.9 of 6400 on GPT-2 XL), and MEMIT's covariance term is worth 7.9–11.4×/6.6–11.9× in leakage. The follow-up worth running is the one thing that measurement cannot settle — whether leakage onto held-out keys predicts the downstream generality scores that editing papers actually report. That needs a benchmark run, not linear algebra.

3 · Measure the reach, then fix MEMIT's coefficients. Forward passes only, no training. The critique of the 1/(L−ℓ+1) rule is already published; the measurement that would replace it is not.

Not 4 · pole placement on the SSM layers of a hybrid. It is the one place the mathematics applies with zero analogy-stretching, and truncation has already been done there. But it is a different project from teaching a model a domain, and it should not be smuggled into this one.
